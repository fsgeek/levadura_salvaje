# Review of plumbing spike 1 (Codex, verbatim)

**Verdict: useful spike; proceed after fixes. “17/17” supports a narrow, static import—not the broader identity, paging, or evidence guarantees.** Static review only; I did not run it.

1. **HIGH — `cited` silently discards conflicting outcomes, twice.**  
   [spike.py:140](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:140) merges `{code_section: section_outcome}` inside each part. AQL `MERGE` takes the later value for duplicate keys; the resolution query has no ordering. [ArangoDB semantics](https://docs.arango.ai/arangodb/stable/aql/functions/document-object/#merge). Then [spike.py:156](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:156) overwrites conflicts across parts with Python `update`. **Checking conflicts only at the top would already be too late.** Distinct cardinality remains correct; the outcome histogram can depend on merge order. Ledger histogram equality cannot prove per-address agreement. Preserve outcome sets per address and reject/report sets larger than one before collapsing.

2. **HIGH — The oracle verifies pagination mechanics, not correct evidence or correct cells.**  
   [check.py:64](/home/tony/projects/levadura_salvaje/spikes/plumbing1/check.py:64) repeats `drill`’s predicate over the same imported resolutions. Wrong resolution outcomes or substituted section IDs can affect both identically. Moreover, [check.py:80](/home/tony/projects/levadura_salvaje/spikes/plumbing1/check.py:80) compares only the **global** member set: swapping memberships between parts can pass, including totals computed from those same wrong memberships. Nothing compares each drill to its persisted rollup state. Duplicate/total checks are redundant or self-consistency checks, not independent acceptance. Use explicit source-derived expected IDs **per cell**, and compare rollup, unpaged query, and concatenated pages separately.

3. **MEDIUM — “Honest paging” is untested and has a boundary bug.**  
   [spike.py:180](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:180) declares `truncated` whenever a page is full—even when exactly `limit` members remain. [check.py:73](/home/tony/projects/levadura_salvaje/spikes/plumbing1/check.py:73) ignores that field and fetches an extra empty page. It checks `population_total` only on the last page. The returned cursor merely describes a binding: `drill` accepts separate `m`, `part`, and `after` arguments and validates no cursor binding. Test 0/39/40/41/80 members, every page’s metadata, wrong-cell/manifest cursors, and concurrent publication. Fetch `limit + 1` to determine truncation.

4. **HIGH — Manifest pinning is cosmetic outside the single-load fixture.**  
   [spike.py:132](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:132) counts **all** sections/citations but filters resolutions by manifest. Resolution keys omit the manifest; replacement imports overwrite previous assertions ([spike.py:96](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:96), [110](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:110)). Deleted source rows remain. A corrected import therefore destroys historical answers and can mix denominator generations. The manifest is published before its data ([spike.py:70](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:70)). Deferring corrections is legitimate; claiming cursor/manifest stability from this implementation is not.

   - **Identity:** [spike.py:85](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:85) compares ordered paths/spans, then imports stored citations and recovers `group`. Useful traversal alignment for this fixture; no stability across extraction changes, no full-field comparison, no legacy age/moved-row reconstruction. A mismatch still loads with `group=None`.
   - **Idempotency:** [check.py:46](/home/tony/projects/levadura_salvaje/spikes/plumbing1/check.py:46) checks counts only. Arbitrary document changes—or a no-op second load—pass. Provisions have no source-count assertion; import error reports are ignored.
   - **Changed content:** [check.py:104](/home/tony/projects/levadura_salvaje/spikes/plumbing1/check.py:104) changes the expected hash, not file contents. It tests mismatch reporting, not cache invalidation. The cache uses path/mtime/size, not content identity ([spike.py:207](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:207)).
   - **Evidence:** [check.py:86](/home/tony/projects/levadura_salvaje/spikes/plumbing1/check.py:86) samples arbitrary non-null citations, not drill members or 20 members per metric. Section-number substring containment does not validate the requested subdivision or group association. Hash domains are declared but not dispatched/validated by `follow`.

Aggregation recomputes imported resolver labels; it does not independently resolve against the loaded USC provisions or verify every source-text hash. `SPECS` is unused descriptive text ([spike.py:120](/home/tony/projects/levadura_salvaje/spikes/plumbing1/spike.py:120)); no executable metric contract or rollup-reading API exists.
